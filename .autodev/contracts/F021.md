# F021 contract: published public API contract for clients

## Why now (facts checked on `autodev/F021`, 2026-11-15)
- The only real public surface today is `geneforgelang.core.api` (`__all__`, 10 names). `geneforgelang/__init__.py` advertises `parse/validate/execute/infer` but imports nothing (F010 restores the facade).
- No grammar version exists in code. `get_api_info()` hard-codes `api_version`/`gfl_version` = `"0.1.0"`; `pyproject.toml` and `__version__` say `1.0.0`; the latest tag is `v0.2.4`.
- `execute()` dispatches to built-in plugins that use `random` (`plugins/builtin/protein_generator.py`, `simple_optimizer.py`), `infer_enhanced()` and `compare_inference_models()` use the heuristic engine / `DummyGeneModel`. `infer()` runs whatever model the caller passes. These are simulated output unless the caller supplies a measured model (QB-6).
- `docs/spec/versioning_policy.md` states SemVer for biology; nothing enforces it.

## Scope
Adds:
- `src/geneforgelang/public_contract.py`: single source of the contract. Constants `CONTRACT_VERSION` (SemVer of the client-visible surface) and `GRAMMAR_VERSION`; `EVIDENCE_LABELS` (per public function: `computed` or `simulated`, with a reason); `build_contract()` introspects the code (`api.__all__`, `inspect.signature`, `ErrorCodes`, `ErrorSeverity`, `ErrorCategory`, the public error classes, top-level keys the parser emits for the conformance constructs) and returns a JSON-able dict; `compare(baseline, current, changelog_text)` returns a list of violations; CLI `python -m geneforgelang.public_contract --write | --check | --against <git-ref> | --check-tag <tag>`.
- `docs/spec/public_contract.json`: generated snapshot (never hand-edited; `--check` fails if it differs from the code). `docs/spec/API_CONTRACT.md`: short human page that points to the snapshot and states the rules (SemVer mapping, evidence labels, how to bump).
- `tests/contract/test_public_contract.py`.
- `.github/workflows/contract.yml`: new workflow (kept apart from `ci-pipeline.yml`, which F003 rewrites and team branches edit). Jobs: snapshot check, `--against origin/<base>` on pull requests, `--check-tag` on `v*` tags.
- `CHANGELOG.md`: an entry for the contract under `[Unreleased]`.
- Small edit in `core/api.py::get_api_info`: `api_version` and `gfl_version` read `CONTRACT_VERSION` and `GRAMMAR_VERSION` (removes the 0.1.0 drift).

Does not change: any signature of a public function, the validator or parser behaviour, `ci-pipeline.yml`, `pyproject.toml`, the package `__version__` (F011 unifies it; this feature only checks it).

Sensitive paths touched (owner review gate): `.github/workflows/**` (new file), `core/api.py` (3 lines).

## Rules the contract encodes
- Surface = for each public name: kind, module, signature (parameter names, kinds, annotations as text, defaults as repr, return annotation); error codes (name to value) and enum members; grammar version; evidence label.
- Classification of a change against a baseline: removed name, removed/renamed/re-ordered parameter, removed enum member or error code, changed default, new required parameter, changed grammar MAJOR = **breaking** (needs MAJOR bump). New name, new optional parameter, new enum member or code = **additive** (needs MINOR bump at least). Evidence label change = at least MINOR; `simulated` to `computed` is additive, `computed` to `simulated` is breaking. Doc-only change = no surface diff.
- Every non-empty diff also needs a `CHANGELOG.md` line that mentions the new contract version in the form `Contract X.Y.Z`.

## Done means
- **D1 (acceptance 1).** Run `uv run --no-project --python .venv python -m geneforgelang.public_contract --check`: exit 0. Edit one public signature in a scratch copy (e.g. rename a parameter of `parse`): the same command exits non-zero and names the change. `docs/spec/public_contract.json` contains: the 10 names with signatures, the error codes, `contract_version`, `grammar_version`, the evidence labels. The snapshot is produced by `--write` and the file header says so; no name or signature is typed by hand in the test.
- **D2 (acceptance 2).** `tests/contract/test_public_contract.py` runs `compare()` on synthetic baseline/current pairs built from the real contract and asserts: removed name without bump fails; removed name with MAJOR bump but no changelog line fails; with both passes; added name with only a PATCH bump fails; added name with MINOR bump plus changelog passes; label `computed` to `simulated` needs MAJOR. Also an integration check on a real git repo: in a temp git repo copy of the snapshot, `--against HEAD~1` style comparison via `git show` fails for a mutated snapshot. Grammar construct: for each construct in a fixed list (`experiment`, `design`, `optimize`, `rules`, `hypothesis`, `timeline`, `pathways`, `complexes`, the ones that `tests/conformance_suite` and `docs` already name), the snapshot records that `parse()` of a minimal sample yields that top-level key; removing support makes the contract check fail (test mutates the recorded construct list, not the parser).
- **D3 (acceptance 3).** `--check-tag v1.0.0` exits 0 when `pyproject.toml` version, `geneforgelang.__version__` and the tag agree; exits non-zero naming each disagreement for `v9.9.9` and for a pyproject/`__version__` mismatch (tests use a temp pyproject, not the real one). `.github/workflows/contract.yml` runs it on `refs/tags/v*` using `GITHUB_REF_NAME`; `actionlint` (or `python -c "yaml.safe_load"` if actionlint is absent) parses the file. Whether the workflow runs on GitHub is verified after the PR is pushed: record the run URL or state that CI could not run (owner gate: merge).
- **D4 (acceptance 4).** Every public function has an entry in `EVIDENCE_LABELS` (a test fails when `api.__all__` gains a name without a label, and when a label is outside `{measured, computed, simulated, stub}`). `execute`, `infer`, `infer_enhanced` and `compare_inference_models` are labelled `simulated` with the reason; `parse`, `validate`, `validate_plugins`, `list_available_plugins`, `parse_enhanced`, `get_api_info` are `computed`. A test shows the labels are not decoration: `execute()` on a design block returns sequences from `random` (assert the plugin module imports `random`, and that two seeds differ), which is the evidence for `simulated`.
- **D5 (drift).** `get_api_info()["api_version"] == CONTRACT_VERSION` and `["gfl_version"] == GRAMMAR_VERSION` (test).
- **D6 (regression).** Full suite `uv run --no-project --python .venv python -m pytest tests -q -p no:cacheprovider`: 0 failed, skipped/xfailed no higher than baseline; `ruff check src tests` clean; `language_check.py --diff autodev/integration`: 0 findings.

## Amendments after the evaluator review (`F021-review.md`)
Each remark is adopted unless a deviation is stated.
- **R1 (grammar version).** Deviation from the suggestion "derive from the highest suite directory": `GRAMMAR_VERSION = "1.2.0"` because v1.3.0 to v1.5.0 are not implemented (A1). A test ties it to the suite: directory `tests/conformance_suite/v<GRAMMAR_VERSION>` must exist, and the contract's `unimplemented_suites` must equal the sorted suite directories above it. Bumping `GRAMMAR_VERSION` without that directory fails.
- **R2 (simulated evidence).** `execute()` has no seed parameter, so D4 compares two `execute()` calls on the same `design` block (count 10): sequences differ (probability of equality is negligible: random 20-letter choices). The test does not inspect imports. `EVIDENCE_LABELS["infer"]` reason says: "simulated unless the caller passes a measured model; the library ships none".
- **R3 (grammar constructs).** Construct samples are the first valid `.gfl` file under `tests/conformance_suite/v<GRAMMAR_VERSION>/<area>/` plus one inline sample per construct for those the suite lacks. The contract records, per construct, the top-level key `parse()` returns. Removing a construct (the key is no longer produced) = breaking; adding one = additive; a change in a sample's validation result (valid to invalid) = breaking. A test monkeypatches `api.parse` to drop one construct and asserts `--check` fails and names it (parser behaviour, not the recorded list).
- **R4 (`--check-tag`).** It compares the given tag name (with or without leading `v`) to `pyproject.toml` version and `geneforgelang.__version__`; the tag need not exist in git. `--pyproject <path>` selects another pyproject (used by tests with temp files). D3 uses the version read from the real pyproject at verification time (not the literal `1.0.0`), so F011 changing it does not break the check.
- **R5 (`--against`).** `--against <ref>` reads the baseline snapshot with `git show <ref>:docs/spec/public_contract.json` and the changelog from the **working tree** (the change under review carries its own entry). If the ref has no snapshot (first PR), it prints "no baseline snapshot at <ref>" and exits 0 with a notice; this is explicit in the workflow. The test runs the CLI with `cwd` in a temp git repo with two commits (original and mutated snapshot) and asserts exit != 0 and the change name in stdout.
- **R6 (workflow).** Validate with `actionlint` installed via `uv tool run`/pip if available; otherwise record in the progress entry that only YAML syntax was checked. The PR text is prepared in `.autodev/contracts/F021-pr.md` (sections: What it does / Why / How to reproduce / Impact on results). Merge and the first GitHub run are owner gates.
- **R7 (evidence paths).** Every D writes its command output and exit code into `.autodev/evidence/F021/` (`checks.txt`, `d1-check.txt`, `d1-mutation.txt`, `d3-tag.txt`, `d6-suite.log`).
- **R8 (D1 mutation).** Done through a pytest test that monkeypatches the signature of `api.parse` (and a CLI run with `PYTHONPATH` pointing to a temp copy of the package for the exit-code evidence). The real source is never edited for the check.
- **R9 (baseline).** Baseline recorded on this branch before changes: `986 passed, 22 skipped, 10 xfailed` (`.autodev/evidence/F021/baseline.log`). D6 requires no more failures and no more skips/xfails than that.
- **R10 (rules).** Evidence order: `stub < simulated < computed < measured`; moving up is additive, moving down is breaking. Grammar version: a change in `GRAMMAR_VERSION` MAJOR requires a MAJOR contract bump; MINOR a MINOR bump at least; PATCH a PATCH bump at least. Public error classes: `EnhancedValidationError`, `EnhancedValidationResult`, `ErrorSeverity`, `ErrorCategory`, `ErrorCodes`, `GFLSyntaxError`, `ExecutionError` (the ones `core/api.py` raises or returns); removing one or one of its public attributes/methods signatures is breaking. The snapshot also records `v2025.06-initial-stable` is not a version tag and is ignored by the tag check.
