## Deeper version

1. **The professional's move (application-security engineer handling a leaked credential in a public OSS repo).** Treat the secret as compromised: removing it from the tree does not un-leak it, so rotation comes first and the purge is cosmetic. Prevent recurrence at two layers (developer hook and server-side CI), because hooks are optional for contributors, and make the CI config tamper-resistant (config from the base commit). Remove the deserialization attack surface instead of wrapping it, and write the rule down.
2. **The rawest material.** `git ls-files` and the tracked tree; the code's real `getenv` references (not the secret file); gitleaks' upstream default rules; the official release checksums.
3. **Methods and tools.** gitleaks v8 in staged, commit-range and directory modes; SHA-256 verification of tooling; OpenSSF Scorecard Pinned-Dependencies and Token-Permissions practices; a negative test with a run-time synthetic AWS-format key plus a positive control; hygiene rules as pytest so the suite enforces them.
4. **The external oracle.** gitleaks (third-party scanner, upstream rules) reports zero on a clean export of HEAD and on the branch commits, and fires on the synthetic key through both the pre-commit hook and the CI script; `git check-ignore` for the ignore rules. A hosted GitHub run (owner-gated) and a future Scorecard run complete the oracle.

**Restated task:** remove `.devcontainer/.env` and every pickle artifact from the tracked tree without reading the secret; prove with gitleaks (upstream rules) that HEAD's tree and the branch commits are clean; prove with a run-time fake AWS key and a positive control that both the pre-commit hook and the CI script block a leak; pin every CI dependency immutably and load the scan config from the trusted base; record the no-pickle rule as an ADR; give the owner a values-free rotation list and a separate purge decision; keep `.autodev/` out of the public PR.
