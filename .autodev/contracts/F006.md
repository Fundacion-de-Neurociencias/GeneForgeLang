## Assumptions (falsifiable)
- The validator accepts or rejects each case as measured on 2026-11-16 (9 pass, 27 fail). Falsified if the counts differ on a clean checkout.
- `python -m geneforgelang.conformance` needs the repository root as the working directory because `plugins/plugin_registry.py` imports `src.geneforgelang...` (F013 owns that fix). Falsified if it runs from another directory.
- Expectations come from each case's documented intent (header or description), not from validator output.

## Deeper version
- Oracle: a case-by-case comparison with an expectation written from the specification text, plus a mutation check on the runner itself (a wrong expectation must fail; a stale known-failure entry must fail). The expected outcomes are not derived from the validator's own output, so a validator regression changes a result and is seen.
- Limits stated: the mutation score of the validator is not part of this feature (QB-4, separate).
